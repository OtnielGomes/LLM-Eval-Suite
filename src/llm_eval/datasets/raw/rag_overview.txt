# Retrieval-Augmented Generation (RAG)

## What is RAG?

Retrieval-Augmented Generation (RAG) is an architecture that combines a retrieval system with a generative language model. Given a user query, the system first retrieves relevant documents from an external knowledge base, then conditions the LLM on those documents to generate a grounded response.

RAG reduces hallucinations by anchoring the model's response in retrieved evidence. It allows the model to access up-to-date or domain-specific information without retraining or fine-tuning. The quality of the final answer depends jointly on retrieval quality and generation quality.

## Chunking

Chunking splits documents into smaller pieces before indexing. The chunk size directly affects retrieval quality:

- Small chunks (100–300 tokens): higher retrieval precision, but may lose context. A relevant passage split mid-sentence will have degraded embedding quality.
- Large chunks (500–1000 tokens): preserve context and discourse structure, but introduce noise from irrelevant sentences within the chunk.
- Semantic chunking splits at natural boundaries (sentences, paragraphs, topic shifts) rather than fixed token counts. This preserves coherence and typically improves embedding quality.

Chunk overlap (e.g., 50–100 tokens) prevents important information at boundaries from being split across two chunks with no representation in either.

## Embeddings and Vector Stores

Dense retrieval uses embedding models to map text to high-dimensional vectors. Semantically similar texts have small cosine distances. Common embedding models include text-embedding-3-small (OpenAI), text-embedding-004 (Google), and nomic-embed-text (Ollama, local).

ChromaDB is an open-source vector database for storing and querying embeddings. It supports persistent storage, metadata filtering, and collection management. It is commonly used with LangChain via the langchain-chroma integration package.

## Retrieval Strategies

Naive retrieval (dense similarity search) embeds the query and retrieves the top-k most similar chunks by cosine similarity. It is the baseline strategy — simple and fast but sensitive to vocabulary mismatch between queries and documents.

HyDE (Hypothetical Document Embeddings) generates a hypothetical answer to the query using an LLM, then uses the embedding of that hypothetical answer to retrieve documents. This bridges the vocabulary gap between short queries and longer passages, typically improving recall by 10–15% on knowledge-intensive tasks.

Re-ranking retrieves a broader candidate pool (e.g., top 3k chunks) and then reorders them by relevance using a cross-encoder or LLM-as-judge. Re-ranking improves context precision — fewer irrelevant chunks reach the LLM — without increasing the initial retrieval latency significantly.

## RAGAS Evaluation Framework

RAGAS provides reference-free and reference-based metrics for evaluating RAG pipelines:

- Faithfulness: whether all claims in the generated answer are supported by the retrieved context. Computed as supported_claims / total_claims.
- Answer relevancy: whether the generated answer actually addresses the question, independent of factual correctness.
- Context recall: whether all information needed to answer the question is present in the retrieved context, measured against a ground-truth answer.
- Context precision: whether relevant chunks appear at the top of the ranked retrieval list (signal-to-noise ratio).
